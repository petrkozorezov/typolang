# Прежние примеры прототипа

Примеры относятся к [прежней машине открытых выражений](../../docs/architecture/obsolete/open-expression-machine/README.md).
Они сохранены как материал для сценариев нового основания. `bind/reduct`, HNF
и приведённые формы больше не задают текущий контракт языка или готовые тесты.

## Связывание и открытые зависимости

```lisp
(bind (lambda (a b) a) (list :ready))
```

Получена остаточная lambda с параметром `b`, тело не редуцировано.
Исходная функция пригодна для независимого связывания.

```lisp
(reduct (bind (lambda (a b) a) (list :ready (hole))))
```

Результат — `:ready`; второй аргумент не востребован. При замене тела на `b`
результат зависит от hole и остаётся открытым.

## Граница головной редукции

```lisp
(reduct (lambda (x) (bind (lambda (y) y) (list x))))
```

Результат — `(lambda (x) x)` с сохранённым объявлением параметра.

```lisp
(reduct (lambda (x) (cons (hole) nil)))
```

Голова под lambda — `cons`; его части не востребованы. Аналогично получение
карты с известными ключами не требует значений невостребованных полей.

## Явная правка со ссылкой

Исходная функция — `(lambda (x) (cons x nil))`. Программа разбирает её структуру,
получает готовую ссылку на `x` и заменяет хвост тела новой парой с той же ссылкой:
получается `(lambda (x) (cons x (cons x nil)))`.

После связывания с `:ready` последовательное наблюдение элементов даёт два
значения `:ready`; исходная функция по-прежнему даёт одно. Замена намеренно
меняет поведение: нужны валидация графа и сохранение ссылок, а не доказательство
эквивалентности. Затем тот же перенос проверяется для внешнего захвата.

Осталось написать этот сценарий средствами самого языка. Он должен проверить
API разбора и сборки кода и показать, нужны ли ещё `quote/unquote` при явном
`reduct`. До этого его нельзя считать исполняемым тестом.
