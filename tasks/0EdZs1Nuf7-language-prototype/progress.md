# Состояние проработки

Текущие решения и восемь пунктов плана находятся в [design.md](design.md),
общие принципы — в [vision](../../docs/product/vision.md). Реализация не начата,
каноническая грамматика не завершена, примеры не исполнялись. Ни один пункт
плана пока не объявлен полностью закрытой спецификацией.

Обсуждение сохранено по запросу от 2026-10-09. Далее накапливать решения
в диалоге; обновлять файлы только по новому явному запросу. Работать без сабагентов.

Ключевые изменения относительно прежнего сохранения:

- Только именованные аргументы; `{a}` наследует внешнее значение, обычные ссылки
  не затеняются полями карты. Внутренние связи задаются явным `rec`; `let` — сахар.
- Применение составлено из `bind`, проверки полноты, `bind_defaults` и `reduct`.
  Последний отдельно позволяет редуцировать тело без полноты и выбора дефолтов.
- Карты неупорядочены. Порядок проверок образца свободен, приоритет ветвей сохранён.
  Закрытые образцы, `...` и `...rest` явно задают допустимость дополнительных полей.
- Пути, окружение и неизменяемая правка общие для агента и редактора.
  Hole адресуется собственной идентичностью. Введение входов требует явной правки
  охватывающей области; готовые внешние ссылки сохраняются.
- Единый валидатор графа кода отделён от проверки типов и графа вызовов
  по итоговой группе изменений. Оптимизационная правка расширяет обычную;
  проверяющая функция не ищет доказательства.

Точка продолжения: последнее предложение раздела 3 о сравнении атомов и ключей
по идентичности без общего глубокого равенства ещё не подтверждено отдельно.
Затем замкнуть представление объявлений/ссылок и канонические формы, включая
соотношение `eval` с `reduct`, API путей и проверки графа. Не возвращаться к обзору
возможностей и не разрабатывать сейчас стратегии оптимизатора или тотальность.

До реализации нужны подготовка по workflow и первый исполняемый эксперимент
для выбора языка. Полноценный прототип должен запустить исполнитель ядра
на typolang; машинный код, GUI и постоянное хранилище остаются за первым срезом.

Проверки этого сохранения: перечитывание изменений, `git diff --check`,
`task-check`, локальные ссылки и баланс скобок примеров. Они проверяют документы,
не семантику будущей машины.
