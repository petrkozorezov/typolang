# Применение функций

Позиционный вызов выбран как простое основание для проверки открытых выражений.
Обязательная карта аргументов смешивала эту задачу с проектированием именованных
интерфейсов и усложняла построение упорядоченных списков. Её
[отложенная модель](../obsolete/map-argument-model.md) сохранена для сравнения; возвращение
должно обосновываться конкретным преимуществом, возможно на уровне адаптера.

## Параметры и арность

```lisp
(lambda (a b) body)
(f x y)
```

Lambda имеет конечный список простых имён параметров. Аргументы позиционные;
их значения ленивы. Вызов — одно применение, не раскрытие через каррирование.
Структурные образцы используются в `match` в теле: это оставляет один механизм
сопоставления. Дефолты, именованные аргументы и вариативные параметры пока убраны.
Они добавляли правила закрытия интерфейса, выбора значений и накопления остатка,
не необходимые для проверки основной идеи.

Применение связывает свободные параметры по порядку:

- Недостаток аргументов создаёт остаточную функцию с оставшимися параметрами.
- При точном количестве результатом становится тело с этими связываниями,
  вычисляемое лениво по требованию.
- Избыток аргументов — ошибка; они не передаются автоматически возвращённой lambda.

Связанные входы исключаются из доступного интерфейса; исходная функция остаётся
пригодной для независимых применений. Rebind уже занятого входа не допускается.
Позиционный вызов заполняет свободный префикс; произвольное связывание входа
по идентичности требует отдельного уточнения общего API выражений.

Предоставленный hole считается аргументом. Полнота связываний не требует
известности значений. Вызов `(f)` не добавляет связываний функции с оставшимися
параметрами; для нулевой арности `(lambda () body)` он предоставляет тело.
Неизвестная функция оставляет применение открытым; известное неприменимое
значение даёт ошибку при востребовании вызова.

## Частичное применение без обязательной редукции

Задача частичного применения — предоставить зависимости постепенно.
Для этого достаточно сохранить тело и связывания. Оно не обязано редуцировать
тело даже там, где часть результата уже известна:

```lisp
((lambda (a b) a) :ready)          ; остаточная функция, ожидающая b
((lambda (a b) a) :ready (hole))   ; :ready
```

Оставшийся параметр сохраняется в интерфейсе, даже если тело его не использует.
Это позволяет завершать частичный вызов последующим применением.
Однако `(f x y)` не равнозначно `((f x) y)` для произвольной `f`: унарная функция,
возвращающая lambda, отвергает два аргумента в одном вызове.

От обязательной редукции отказались, поскольку она требует определить глубину
специализации и добавляет работу, не нужную для получения остаточной функции.
Специализация возможна отдельно; раннее упрощение реализацией не должно вызывать
преждевременные ошибки или подменять наблюдаемый исходник. Связывание и вычисление
различаются семантически, но отдельные формы `bind`, `reduct`, `bind_defaults`
и `reduct_all` в текущем основании не нужны.

При полном применении редукция проходит необходимую цепочку вызовов, а не один
шаг. Полученная lambda остаётся значением; её тело не раскрывается автоматически.
Захваченные открытые зависимости не становятся её собственными параметрами.
Пересмотр границы частичного применения нужен только при сценарии, требующем
другого наблюдаемого поведения, а не ради обязательной ранней оптимизации.

## Применение списка аргументов

`(apply f (list x y))` имеет ту же семантику, что `(f x y)`. Это нужно для
программно собранных вызовов и будущего self-hosted исполнителя, без нового
способа связывания. Исследуется только структура списка, необходимая для проверки
арности; значения элементов ленивы. Для функции двух аргументов обнаружение
третьего уже устанавливает избыток, остаток хвоста не нужен. Неизвестное
продолжение может оставить проверку открытой.

## Локальные алиасы

Нерекурсивный `let` раскрывается через применение lambda:

```lisp
(let ((a x) (b y)) body)
((lambda (a b) body) x y)
```

Правые части используют внешнюю область; тело получает локальные имена.
Отдельный механизм исполнения алиасов не нужен. Рекурсивные группы задаёт
[конструктор карты](data.md#рекурсивные-поля); `letrec` и рекурсивный `let`
пока не вводятся. Удобную запись можно пересмотреть, если использование карт
для таких групп окажется недостаточным. Механизм раскрытия пользовательских
связывающих форм остаётся [открытым вопросом](code.md#базовые-и-пользовательские-формы).

Осталось закрепить каноническое представление параметров и вызова, сигнатуры
прочих примитивов и связывание произвольного входа по идентичности. Возвращать
расширенные интерфейсы следует после проверки этого основания.
