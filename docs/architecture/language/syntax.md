# Синтаксис T-expr

T-expr записывает типизированные деревья скобками или отступами.
Обе записи дают одно дерево. Чтение строит данные; их смысл определяет язык.

## Значения и литералы

Синтаксис различает символы, атомы, списки и карты.

| Запись | Значение |
| --- | --- |
| `name` | Символ с именем `name` |
| `:atom` | Атом с обозначением `atom` |
| `nil`, `()` | Пустой список |
| `(f x)` | Список символов `f` и `x` |
| `{name: :ada}` | Карта с ключом `:name` и значением `:ada` |

Специальный символ `nil` обозначает пустой список; `:nil` — обычный атом,
`@"nil"` — обычный символ. Пустой список и пустая карта `{}` различаются.

Обычное имя — символ. Экранированные символы: `@"имя с пробелом"`, `@"some:name"`.
Атом записывается как `:имя` или `:"имя с пробелом"`: `:ready`, `:not-found`.
Одинаковые обозначения задают один атом, в том числе в разных модулях.
`name` и `:name` различаются: символ и атом.
`:null`, `:true`, `:false` — обычные атомы; записи без `:` — символы.
Двоеточие в обычном имени запрещено.

Кавычки используются только для экранирования имён. Внутри допустимы
`\"`, `\\`, `\/`, `\b`, `\f`, `\n`, `\r`, `\t`, `\uXXXX`;
управляющие символы экранируются. Суррогатная пара `\uXXXX\uXXXX` задаёт
один символ; одиночные суррогаты запрещены.

Исходный текст — UTF-8. Символы, атомы и ключи поддерживают Unicode
по умолчанию: `данные`, `:готово`, `:"Привет 🌍"`, `{имя: :Ада}`.
Имена сравниваются по последовательности кодовых точек без Unicode-нормализации.

Комментарий начинается с `;` вне кавычек и продолжается до конца строки.
В явных скобках запятые — необязательные разделители.

## Скобки и отступы

`()` — список, `{}` — карта. Внутри скобок переводы строк
разделяют элементы; отступы не группируют их, блочные маркеры запрещены.

Вне скобок элементы строки и её непосредственные дочерние выражения образуют
список. Единственный элемент остаётся самим собой:

| Отступная запись | Скобочная запись |
| --- | --- |
| `f a b` | `(f a b)` |
| `f` | `f`, а не `(f)` |

```text
f a
  g b
  c
```

Это `(f a (g b) c)`: дочерние выражения добавляются к списку строки,
вложенные списки не склеиваются. Для `(f a b c)` нужны отдельные дочерние
строки `b` и `c` либо явные скобки.

Явное выражение остаётся одним элементом:

```text
(f a)
  b
```

Это `((f a) b)`. А внутри скобок перенос не создаёт вложенности:

```text
(f a
  b c)
```

Это `(f a b c)`.

Отступы состоят из пробелов. Соседние выражения блока имеют одинаковый отступ;
уменьшение возвращает к открытому уровню. Пустые строки и строки комментариев
игнорируются. Рекомендуемый шаг — два пробела; чтение не зависит от его ширины.

## Блочные коллекции

| Маркер | Содержимое блока |
| --- | --- |
| `():` | Элементы списка |
| `{}:` | Поля карты |

Маркер требует непустого вложенного блока.
Пустой список — `nil` или `()`, пустая карта — `{}`.
Блок `():` с единственным `x` даёт `(x)`.

```text
{}:
  server: {}:
    host: :localhost
    protocol: :http
  features: ():
    :holes
    :atoms
```

Эквивалентная запись:

```text
{server: {host: :localhost, protocol: :http}, features: (:holes :atoms)}
```

Маркер стоит на отдельной строке или справа от `key:`. Запись `server: {}:`
равнозначна `server:` с дочерним блоком `{}:`. В конец вызова маркер
не добавляется: коллекция передаётся отдельным аргументом.

```text
connect
  {}:
    host: :localhost
    protocol: :http
```

## Карты

Ключи — атомы: `name:` и `"name":` задают ключ `:name`.
Кавычки в ключе экранируют его обозначение. Поэтому `{name: name, status: :ready}`
содержит ключи-атомы `:name`, `:status`, символ `name` и атом `:ready`.

Поля допустимы только внутри `{}` или `{}:`. Порядок незначим.
Повтор ключа после декодирования экранирования — ошибка:
`{name: :ada, "name": :bob}` недопустимо.

Значение поля — одно выражение справа от двоеточия или в дочернем блоке:

```text
{}:
  result:
    f x
```

Это `{result: (f x)}`. Поле без значения и несколько соседних дочерних
выражений — ошибки. Коллекцию или последовательность задают явно:

```text
{}:
  expressions: ():
    f x
    g y
  result:
    do
      f x
      g y
```

Первое поле — список `((f x) (g y))`, второе — список `(do (f x) (g y))`.
Смысл `do` определяет язык.

### Сокращения и расширение

| Запись | Смысл |
| --- | --- |
| `{a}` | То же, что `{a:a}` |
| `{a, ...rest}` | Поле `a:a` и поля карты `rest` |
| `{...rest}` | Поверхностная копия карты `rest` |
| `{a, ...}` | Поле `a:a` и неназванный остаток |
| `{...}` | Только неназванный остаток |

При построении `a` и `rest` берутся из окружения;
значения полей `rest` сохраняются без вычисления. Повтор ключа, в том числе
между явным полем и `rest`, — ошибка. `...` без имени имеет смысл только
в паттернах. Эти записи допустимы и в блоке:

```text
{}:
  a
  ...rest
```

### Вложенные поля

Путь в ключе сокращает вложенные карты. Общие промежуточные пути объединяются:

```text
{}:
  server.host: :localhost
  server.protocol: :http
  server.tls.enabled: :true
```

Это то же дерево, что:

```text
{server: {host: :localhost, protocol: :http, tls: {enabled: :true}}}
```

Правило действует и в скобках: `{a.b: x, a.c: y}` равно `{a: {b: x, c: y}}`.
Справа от пути допустимы обычные значения и блочные коллекции.

Сегмент пути — обозначение атома, записанное обычным именем или в кавычках.
Точка внутри кавычек входит в обозначение: `"a.b": x` задаёт одно поле,
`a."b.c": x` — поле `:"b.c"` внутри `:a`.
Пустые сегменты `.a`, `a.`, `a..b` запрещены.

Повтор полного пути — ошибка: `{a.b: x, "a"."b": y}`.
Явное значение нельзя расширять дочерними полями:
`{a: x, a.b: y}` и `{a: {b: x}, a.c: y}` недопустимы при любом порядке полей.
Объединяются только промежуточные карты, созданные путями.
В дереве остаются обычные вложенные карты. Вне ключа точка этим правилом
не интерпретируется.

## Lambda

`λ` — равнозначная Unicode-запись формы `lambda`:

```text
(lambda (x) x)
(λ (x) x)
```

Отступная запись той же функции:

```text
λ (x)
  x
```

## Чтение

`readOne` читает ровно одно корневое выражение; соседние корневые строки
не объединяются. Чтение не выполняет вызовы и не интерпретирует формы:

```text
defn make-user (name role)
  {}:
    name
    role
    active: :true
```

Это то же дерево, что:

```text
(defn make-user (name role)
  {name: name, role: role, active: :true})
```

```text
readOne(printT(t))   = t
readOne(layoutForm)  = readOne(bracketForm)
```

Равенство относится к деревьям: комментарии, пробелы и выбор скобочной
или отступной записи не сохраняются. Полная лексика имён требует уточнения
перед реализацией. Сокращение `'expr` в `(quote expr)` пока не принято.
