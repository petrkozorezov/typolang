# Структурные термы и данные

Структурные данные строятся цитированием термов. Например, `'(a b c)` описывает
список как данные. Это рабочая нотация, не окончательная грамматика или решение
о внутреннем устройстве списка. Роль цитирования определена в
[работе с кодом](code.md).

## Отношения, функции и карты

Общее основание позволяет описывать соответствие ключа и значения отношением.
Идею конечной карты можно показать метанотацией:

```text
Map(K, V) = (K = 'key1 & V = 'value1)
         | (K = 'key2 & V = 'value2)
```

Здесь явно указаны две компоненты соответствия. Это пояснение идеи,
не выбранная запись конструктора карты.
Функциональное использование отношения требует единственности результата
при заданных входах; наличие результата для каждого входа — отдельное свойство.
Произвольное отношение не получает эти гарантии автоматически.

Именованные структуры должны поддерживать ленивое получение нужного значения,
рекурсивные зависимости и явную композицию. Старое обязательное представление
карты непрозрачным примитивом больше не задаёт способ реализации этих требований.
Объединение отношений также само по себе не определяет политику слияния карт.

## Рекурсия

Рекурсивное определение должно сохраняться конечным описанием со связями.
Бесконечное раскрытие не требуется ни для передачи этого описания, ни для доступа
к доступной части результата. Рекурсия определений и циклическая структура
данных требуют согласованной интерпретации, но не обязаны быть одной операцией.

## Открытые вопросы

- Минимальные структурные конструкторы, представление списков, символов
  и отсутствия значения; какие из них нужны непосредственно основанию.
- Представление карты и функции через отношения, их интерфейсы, проверка
  однозначности, отсутствие ключа и правила композиции.
- Представление рекурсивных определений и ссылок; допускаемые циклические термы
  и правила унификации с ними. Рекурсия сама по себе ещё не задаёт индуктивный тип.
