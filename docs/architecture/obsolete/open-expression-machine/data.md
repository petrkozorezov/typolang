# Данные и рекурсивные структуры

> Устаревшая модель. Примитивные контейнеры и специальный rec больше не заданы новым основанием.
> Документ сохраняет инварианты контейнеров и рекурсивных групп.
> Текущее направление: [соответствующий аспект](../../language/data.md).

Основание использует атомы, пустой список, ленивые пары, карты и функции.
Различия типов сохраняются там, где они дают явные контракты; минимизация числа
представлений сама по себе не является целью.

## Атомы и списки

Идентичность атома определяется обозначением: все записи `:value` обозначают
один атом, включая разные модули. Это позволяет согласовывать ключи и образцы
без импорта отдельного объявления каждого атома. Ключ `value:` использует
соответствующий атом.

Общее глубокое равенство графов не вводится. Сравнение атомов не сравнивает
идентичности параметров или поведение программ; эти различия описаны в
[модели выражений](../../language/expressions.md).

Один ленивый конструктор пары — `cons`. Пустой список `nil` и цепочка пар представляют
списки; отдельный `pair` не нужен. Две части пары могут быть любыми выражениями,
в том числе ключом и значением при обмене с картой.

`list` — форма построения, поскольку пользовательские функции пока имеют
фиксированную арность. `(list a b)` строит `(cons a (cons b nil))`;
пустой `(list)` — `nil`. Это правило интерпретации формы, не вариативная
функция и не отдельная макросная система. Значения элементов остаются ленивыми.

## Карты и их граница со списками

Карта пока отдельный непрозрачный тип с уникальными ключами-атомами, ленивыми
значениями и без гарантии порядка. Ранее предлагался непосредственно список
пар: это давало общий обход, но делало неявными проверку уникальности и границу
порядка списка. Отдельный тип позволяет гарантировать инвариант при построении.
Убрать границу можно позже, если найдётся столь же явный контракт.

Форма карты `{…}` при интерпретации строит карту ленивых выражений.
Ключи явных полей — непосредственно обозначенные атомы.
Сокращения и расширение карт описаны в
[синтаксисе](syntax.md#сокращения-и-расширение). Расширение готовой картой
сохраняет ссылки значений и не вводит лексических объявлений её полей.
`a:value` в конструкторе задаёт поле; обычная пара строится через `cons`.

Карты и списки пар преобразуются друг в друга явно. Динамические ключи доступны
при преобразовании списка: нужно установить весь конечный список, форму его
элементов, атомы-ключи и отсутствие повторов; значения остаются ленивыми.
Неизвестная структура или ключ оставляет проверку открытой, бесконечный список
не подтверждает конечную карту. Проверка выполняется по требованию.
Преобразование сохраняет ссылки значений и не вводит лексических объявлений.

Неизменяемость и контракты операций сохраняют инвариант проверенной карты;
повторная полная проверка при каждом `get` не нужна. Преобразование в список пар
не гарантирует порядок результата. Произвольная списочная операция не обязана
сохранять пригодность к обратному преобразованию.

Повтор ключа запрещён на каждом уровне, включая программное построение.
Вложенные пути раскрываются при чтении по [правилам синтаксиса](syntax.md#вложенные-поля).
Доступ `a.b` — выбор поля через `get`.

## Получение поля и композиция

`get` ленив: получить поле можно без значений остальных полей. Отсутствие поля —
ошибка, открытое значение существующего поля — иной случай. Перечисление ключей
также не требует значений.

`merge` ленив и поверхностен, при совпадении ключей побеждает правая карта.
Для поиска поля устанавливается его наличие справа: наличие позволяет обойтись
без левой карты, отсутствие — искать слева, неизвестность не разрешает выбрать
левое значение. Вложенная карта заменяется целиком; deep merge — отдельная
операция, а не скрытое правило. Это делает композицию конфигураций явной.

## Рекурсивные поля

Явные поля конструктора карты вводят объявления, включая ссылки вперёд.
Обычные имена в значениях разрешаются снаружи, внутренние связи требуют `rec`:

```lisp
{a: :one b:a}          ; b использует внешний a
{a: :one b:(rec a)}    ; b получает :one
{a:(rec b) b: :one}    ; ссылка вперёд
```

Так ключ не затеняет внешнюю обычную переменную, а рекурсия не требует отдельного
модификатора всей карты. `(rec name)` ищет ближайшее окружающее объявление
именно этого поля: карта без него не мешает поиску, одноимённое поле затеняет
внешнее. Отсутствие объявления — ошибка без перехода к обычному имени.
После разрешения сохраняется ссылка, не динамический поиск имени.

Рекурсивные функции, взаимные ссылки и продуктивные структуры используют один
механизм. Например, `{ones:(cons :one (rec ones))}` задаёт бесконечный список.
Обычный вызов функции не создаёт неявных рекурсивных объявлений аргументов.
Для доступа к затенённой связи helper получает её или всю карту явно;
отдельная форма `self` для этого не нужна.

Готовые карты сохраняют связи при композиции. Для `m = {a: :one b:(rec a)}`
слияние с `{a: :two}` даёт новое `a=:two`, но `b=:one`. Правка объявления `a`
внутри новой версии всей группы меняет цель внутренней ссылки вместе с группой;
это [редактирование](../../language/editing.md), а не `merge` или rebind.

Цена `rec` — особое правило лексического поиска, отличное от обычных переменных.
В [Scheme letrec](https://r6rs.org/final/html/r6rs/r6rs-Z-H-14.html) и
[Nix rec](https://nix.dev/manual/nix/2.35/language/syntax.html#recursive-sets)
рекурсивные объявления доступны через обычные имена; наш выбор сделан ради
явной границы внешних ссылок и связей полей. Пересмотр стоит основывать на
конкретном затруднении построения рекурсивной группы или её переноса.

Остались каноническая форма объявлений группы, сигнатуры операций и преобразований,
а также проверка сохранения внешних захватов при переносе.
