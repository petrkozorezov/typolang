# Ядро и библиотека

> Устаревшая модель. Прежний набор примитивов заменён реляционным основанием.
> Документ сохраняет границы ядра и библиотеки.
> Текущее направление: [соответствующий аспект](../../language/core.md).

`core` — набор примитивов построения и наблюдения открытых выражений.
Оно задаёт семантический базис, а не обязательную границу нативного кода.
Сам исполнитель `core`, включая связывание и редукцию, может быть библиотекой
на typolang. Для её первого запуска нужен внешний исполнитель; затем тот же
язык может исполнять собственную реализацию. Самостоятельный запуск требует
отдельного способа исполнения или компиляции этой реализации.

Операции, выразимые через базис, относятся к библиотеке. Это сокращает
независимые правила исполнения и позволяет исследовать и преобразовывать
библиотечные функции средствами самого языка. Нативная реализация может служить
начальным исполнителем или ускорением с тем же контрактом.

## Рабочий состав

| Элемент | Назначение |
| --- | --- |
| `core.input` | Объявить открытый вход с устойчивой идентичностью |
| `core.lambda` | Построить функцию из объявлений параметров и тела, сохранив захваты |
| `core.bind` | Связать параметры доступной lambda со списком аргументов без редукции тела |
| `core.reduct` | Выполнить головную редукцию выражения, в том числе под lambda |
| `core.cons` | Построить ленивую пару |
| `core.nil` | Значение пустого списка |
| `core.map` | Построить непрозрачную карту из пар ключ–значение с проверкой уникальности ключей |
| `core.entries` | Получить пары ключ–значение карты без гарантии порядка и без вычисления значений |
| `core.match` | Наблюдать и сопоставлять структуру данных и выражений |

Это рабочая граница ядра, не окончательные сигнатуры API. Правила идентичностей
задаёт [модель выражений](../../language/expressions.md), арность и связывание —
[применение](application.md), инварианты контейнеров — [данные](data.md),
выбор ветвей и обработку неизвестности — [сопоставление](matching.md).
`core.input` не объединяет атомы, параметры и holes в одну сущность.

Отдельный `core.ref` не нужен: готовая ссылка уже доступна программе и сохраняет
свою цель при переносе. Отдельный `core.apply` не нужен: связывание задаёт
`bind`, запрос редукции — `reduct`. Граница редукции описана в
[вычислении](evaluation.md#головная-редукция). Разделение вычислений и сохранение
открытых зависимостей остаются свойствами исполнителя.

## Библиотека

- `parse` и обработчики форм, включая `list` и `let`, строят выражения через ядро.
- `get` ищет ключ среди записей карты, не вычисляя значения остальных полей;
  `merge` выражает композицию карт с сохранением её ленивого контракта.
- Пути и `context` обходят структуру и собирают доступные объявления.
- `replace` перестраивает выбранный фрагмент и путь к нему, сохраняя связи.
- `validate` проверяет инварианты графа общим процессом для исходного,
  построенного и отредактированного кода.
- Оформление входа как hole добавляет локальный контекст и обязательства
  без отдельного примитива исполнения hole.
- `normalize` выполняет полную нормализацию через `reduct` и структурный обход.

Эта граница требует доступности структуры выражений, объявлений и ссылок
библиотечному коду. Достаточность рабочего набора для такого построения
и обхода ещё нужно проверить. Нативная реализация библиотечной операции
ради эффективности сама по себе не делает её семантическим примитивом.

`match` пока остаётся в ядре: перенос в библиотеку оправдан, если более простые
операции наблюдения позволяют сохранить его контракт без усложнения базиса.

## Цитирование

Явное разделение связывания, исследования структуры и редукции требует
пересмотреть роль `quote/unquote`. Прежняя гипотеза реализации через режим
`parse` не считается готовым решением. Необходимость этой пары и её точный
контракт ещё не установлены; отказ от неё также не принят. Сохраняемые
инварианты — в [работе с кодом](code.md#цитирование-открытых-выражений).
