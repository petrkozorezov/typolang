# Сопоставление с образцами

> Устаревшая модель. Приоритетный match больше не задаёт базовую семантику ветвления.
> Документ сохраняет мотивы приоритета ветвей и симметричных проверок внутри образца.
> Текущее направление: [соответствующий аспект](../../language/core.md).

`match` нужен для ветвления по атомам и структуре ленивых данных. Единый механизм
сопоставления используется в теле функций; отдельные перегрузки и структурные
образцы параметров lambda пока не вводятся.

## Что наблюдает match

Структурное сопоставление исследует переданное выражение без неявного запуска
`reduct`. Имя, связанное с функцией, позволяет исследовать lambda, её параметры
и тело. Для сопоставления с результатом вычисления редукция запрашивается явно.
Точное сочетание структурного доступа и востребования значений в записи
образцов ещё нужно согласовать с `bind/reduct`; приоритеты ветвей и правила
объединения проверок ниже сохраняются.

Выбранное направление — образцы функций в привычной записи `lambda`,
сопоставляемые со структурой открытого выражения. Макросного раскрытия образцов
для этого не требуется. Каноническая запись таких образцов, сопоставление
объявлений и обработка внешних ссылок ещё требуют проработки.
Извлечённое тело сохраняет свои зависимости; совпадение написаний параметров
не означает совпадения идентичностей. Инварианты — в [работе с кодом](code.md).

## Выбранные правила

Ветви `match` имеют приоритет по записи. Следующая выбирается только после
установленного несовпадения предыдущих; исчерпание ветвей — ошибка.
Порядок проверок внутри образца не гарантируется и оставлен рантайму
и оптимизатору в рамках правил объединения результатов ниже: порядок работы
не разрешает выбирать наблюдаемый исход. Вложенные структурные образцы
сохраняются; проверка частей требует установить внешний вид структуры.

| Образец | Требование |
| --- | --- |
| Имя | Связать выражение без вычисления |
| Атом | Получить и сравнить атом |
| Пустой список | Установить пустой список |
| Пара | Установить пару и сопоставить части |
| Карта | Проверить поля и вложенные образцы; закрытость или остаток заданы явно |

Для карты `{a b}` нужны ровно эти поля; `{a b ...}` допускает другие;
`{a b ...rest}` захватывает их без вычисления значений. В обычном `match`
отсутствующее требуемое поле даёт несовпадение. Существующий hole совпадает
с именем без вычисления, но проверка атома или структуры может ждать его значения.
Неизвестная структура карты оставляет проверку открытой.

Результаты независимых проверок объединяются так:

- Одно установленное несовпадение достаточно для отклонения образца.
- Совпадение требует совпадения всех проверок.
- Без несовпадения при незавершённых проверках исход ещё не определён.
- Ошибка окончательна, когда остальные проверки уже не могут отвергнуть образец.

Ошибка вычисления, востребованного сопоставлением, не является несовпадением.
Например, поле `a` в `{a: (get {b: :yes} :missing)}` существует, но проверка
его значения по атому требует ошибочного обращения к отсутствующему ключу.
Это отличается от отсутствия самого поля `a`, которое отвергает образец.
Некорректный образец — ошибка валидации кода, не исход сопоставления.

Ошибка вычисления может оказаться ненужной,
если другая проверка отвергла образец; поэтому первая обнаруженная ошибка
не обязательно прерывает весь `match`. Порядок диагностики нескольких ошибок
не гарантируется. Зависание, справедливость выполнения и стратегии оптимизации
отложены к дальнейшей работе с тотальностью.

Образцы конечны; рекурсивные данные исследуются в востребованной мере.
Локальные имена линейны: повторное объявление запрещено, чтобы не вводить
неявное равенство значений. Атомные образцы сравнивают идентичности атомов,
а не глубокую структуру графа. Остаток `{a ...rest}` относится к образцу карты;
он не вводит вариативные параметры функций.

[Pattern holes](https://hazel.org/papers/peanut-oopsla2023.pdf) — референс
различения совпадения, несовпадения и неизвестности. Множественные результаты
и поиск MeTTa не заменяют выбранный приоритет ветвей.

## Основания выбора и цена

Образец задаёт требования к данным: достаточная известная информация позволяет
отвергнуть его независимо от неизвестной или ошибочной части. Для открытых
выражений это важнее свободы оптимизатора выбирать порядок работы.

Для образца `{a: :yes b: :yes}` известное `b=:no` достаточно для несовпадения,
даже если `a` — hole или его востребование приводит к ошибке вычисления.
Последовательная проверка сначала `a`, затем `b` вместо этого ожидала бы `a`
или завершилась ошибкой. Перестановка полей образца меняла бы поведение,
поэтому их порядок пришлось бы сохранять как семантически значимый,
независимо от неупорядоченности самой карты. После сравнения этот вариант
отклонён; симметричные правила сохранены без изменения семантики.

Цена — необходимость сохранять промежуточные ошибки вычисления. Если `a`
даёт ошибку, а `b` неизвестно, ошибка ещё не окончательна: `b=:no` отвергнет
образец, а `b=:yes` сделает ошибку необходимой. Первую обнаруженную ошибку
нельзя автоматически выдавать как итог всего `match`. Само отсутствие порядка
не доказывает простоту или эффективность исполнения; планировщик, справедливость
выполнения и тотальность остаются отложенными вопросами.

Каноническая запись ветвей и образцов ещё нуждается в проработке.
