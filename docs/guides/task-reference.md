# Метаданные задач

Процесс определён в [workflow](../workflow.md), назначение материалов —
в [схеме хранения](../README.md). Синтаксис CLI и допустимые значения — в `--help`.

## Каталог и постановка

Каталог имеет вид `tasks/<id>-<slug>/`: ID — 10 символов base62, slug — английский
lowercase kebab-case. Каталоги не удаляют, не переименовывают и не перемещают;
ID не переиспользуют. Создание внутри checkout последовательное. При коллизии
ID после объединения веток одной задаче назначают новый ID и исправляют ссылки.
Алгоритм ID определён в [task-id.sh](../../modules/scripts/task-id.sh).

`description.md` содержит заголовок, постановку «что нужно и почему» и метаданные:

```yaml
---
created: 2026-09-22
depends_on: []
tags:
  - tooling
size: m
priority: normal
---
```

`created` соответствует дате из ID. `depends_on` — список полных имён каталогов
зависимостей; непустой список записывается по одному имени на строку.
`tags` — непустой список уникальных тегов области и характера работы.
Словарь определён в [task-common.sh](../../modules/scripts/task-common.sh);
новый тег добавляют только для повторяемого применения.

## Размер и приоритет

Размер оценивает всю поставку, включая исследование, код, тесты и документацию:

- `s` — локальная понятная правка;
- `m` — связанные изменения в одной подсистеме;
- `l` — несколько компонентов или существенное исследование;
- `xl` — крупная неопределённая работа; стоит рассмотреть разбиение.

Приоритет описывает очередь:

- `critical` — авария, критический дефект или блокировка проекта;
- `high` — следующая важная поставка;
- `normal` — обычная задача;
- `low` — отложенная идея или исследование.

Зависимости важнее приоритета; размер не задаёт приоритет. Оценки уточняют при
новых знаниях, сохраняя существенные причины в progress. Фактический результат
не подменяет исходный прогноз задним числом. Метаданные исторических задач,
мигрированных 2026-09-21, ретроспективны и не восстанавливают прежнюю очередь.
