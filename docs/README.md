# Документация

Документы хранят знания, необходимые для использования системы, понимания её
устройства и безопасного изменения. Принципы качества — в [AGENTS.md](../AGENTS.md),
процесс работы с задачами — в [workflow](workflow.md).

Каждый новый документ сюда добавлять не нужно. Тут только основные.

## Постоянные знания

| Место | Назначение |
| --- | --- |
| `product/` | Базовые документы о продукте |
| `product/requirements/<область>.md` | Актуальные обязательства продукта и их основания |
| `architecture/` | Базовое описание архитектуры системы, границы и связи подсистем |
| `architecture/<подсистема>/<аспект>.md` | Что, как и почему устроено; ограничения и инварианты |
| `guides/` | Технические процедуры и справочные форматы |
| Документация рядом с кодом | Локальные API, ограничения и неочевидные детали реализации |
| Тесты | Проверяемые сценарии, включая частные случаи и регрессии |

Документы описывают актуальную систему; история изменений хранится в Git.
Требования и архитектурные описания обновляются на месте. Причины выбора,
существенные альтернативы, ограничения и инварианты находятся рядом с тем,
к чему относятся. Каждое знание имеет один источник истины. По сути
это ADR/INV/REQ без номеров и стататусов лежащие иерархически0

Структура следует предметным областям и устройству системы. Обзоры дают
контекст и точки входа. Каталоги и отдельные документы создаются по необходимости;
для небольшого аспекта достаточно `architecture/<аспект>.md`.
Ссылки ведут на смысловые пути и разделы, без глобальных последовательных номеров
и цепочек замены записей. Отдельный журнал решений нужен только для контекста
исторических событий, имеющего самостоятельную ценность.

## Материалы задачи

Одна задача — одна независимо проверяемая поставка в `tasks/<id>-<slug>/`.
Назначение и метаданные каталога — в [справке задач](guides/task-reference.md).

| Материал | Назначение |
| --- | --- |
| `description.md` | Что нужно и почему; необходимые ограничения и метаданные |
| `design.md` | Предполагаемое решение и основания выбора |
| `plan.md` | Checklist изменений и проверок |
| `progress.md` | Текущее состояние, препятствия и контекст продолжения |
| `review.md` | Активные замечания, ответы и состояние их обработки |
| `result.md` | Фактический итог, проверки и ограничения |
| `.work/` | Временные прототипы, измерения, логи и вспомогательные скрипты |

Материалы создаются по необходимости; обязательных пустых разделов нет.
Постановка не должна заранее содержать дизайн или план реализации.
Design может сохранять исходный замысел во время работы, даже когда решение
уже отражено в архитектуре. Progress редактируется как актуальная записка,
а подробности читаются по ссылкам только при необходимости.

Исторические задачи сохраняют контекст поставки; актуальные требования
и решения находятся в документации продукта и архитектуры.
